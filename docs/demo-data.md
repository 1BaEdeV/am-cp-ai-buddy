# Загрузка демо-данных

Из папки `backend`, после загрузки переменных окружения с `DATABASE_URL`:

```sh
go run ./cmd/seed-demo
```

Команда создаёт таблицы тем же кодом миграции, что API, и загружает встроенные
файлы из `backend/seeds/demo`. Относительный путь к файлам при этом не требуется.
Для загрузки собственного полного набора из восьми YAML-файлов:

```sh
go run ./cmd/seed-demo -dir ./seeds/demo
```

При `DEMO_SEED_ON_STARTUP=true` API загружает встроенные данные после миграции,
до запуска HTTP и фоновой выдачи. В `.env.example` эта настройка включена для
демо; без переменной загрузка при старте отключена. Файл `.env` нужно загрузить
в окружение самостоятельно, как описано в README.

Загружаются команды, должности, наставники, сотрудники, профили, ресурсы,
правила обязательных доступов и начальные подтверждённые доступы. Начальные
права также сохраняются в демо-провайдере, поэтому карточка и фактическая
проверка прав показывают одинаковое исходное состояние.

Загрузчик отклоняет неизвестные поля YAML, несколько документов в одном файле,
дубли ID и уникальных сочетаний, неверные ссылки, роли, уровни и даты.
Все изменения данных, включая права провайдера, выполняются одной транзакцией.
При ошибке данные этой загрузки откатываются. Миграция схемы выполняется отдельно.

Повторный запуск добавляет отсутствующие записи и сохраняет существующие.
Он не сбрасывает регистрацию, изменения справочников, заявки, прогресс и
режимы сбоя провайдера. Поэтому редактирование YAML не обновляет уже
существующую запись в базе. Если исходный ResourceID теперь указывает на другой
внешний ресурс, загрузка начальных прав завершается ошибкой вместо переноса
прав на новое назначение. Счётчики в логе относятся к числу записей во входных
файлах, а не только к новым вставкам.

## Демо-пользователи

| ID | Почта | Исходное состояние |
| --- | --- | --- |
| `intern-alina` | `alina.search@example.test` | Профиль заполнен, Вики и YouTrack выданы: 2/4 |
| `manager-dmitry` | `dmitry.search@example.test` | Руководитель команды «Поиск», согласует GitLab и Grafana |
| `intern-ivan` | `ivan.web@example.test` | Новый стажёр, при входе требуется регистрация |

Для Алины недостающие ресурсы: `gitlab-search-api` и `grafana-search`.
У Ивана исходная должность — `position-frontend`. В каждой команде доступны
3–4 должности, у каждой настроены обязательные ресурсы и уровни доступа.
При регистрации стажёр выбирает команду, одну из её должностей и одного из двух
наставников. Сервер проверяет все три значения.
Полный набор содержит 10 команд, 10 должностей, 20 наставников, 20 сотрудников,
11 исходных профилей, 10 ресурсов и 125 правил доступа для 31 сочетания команды
и должности. У каждого руководителя есть профиль.

| Команда | Должности |
| --- | --- |
| Поиск | Backend Go, тестирование, аналитик данных |
| Веб-интерфейсы | Frontend, Backend Go, тестирование, продуктовый дизайнер |
| Доверие и безопасность | Backend Python, тестирование, аналитик данных |
| Качество продукта | Тестирование, Backend Python, аналитик данных |
| Продуктовая аналитика | Аналитик данных, Data Scientist, Backend Python |
| Рекомендации | Data Scientist, ML-инженер, аналитик данных |
| ML-платформа | ML-инженер, Backend Python, DevOps |
| Инфраструктура | DevOps, Backend Go, тестирование |
| Продуктовый дизайн | Продуктовый дизайнер, Frontend, аналитик данных |
| Эксперименты | Аналитик данных, Data Scientist, Backend Python |

Например, в «Веб-интерфейсах» дизайнеру нужен Figma Editor, frontend-разработчику —
Figma Viewer и GitLab Developer, тестировщику — GitLab Reporter, а backend-разработчику
Figma не требуется. Повторный seed добавляет новые варианты без сброса профилей.

## Контекст AI-buddy

У всех десяти учебных команд есть описание направления, инструментов и первых задач.
У наставников и руководителей — контакты и область помощи. Эти сведения вымышленные.
Они передаются в оба чата вместе с выбранной командой и должностью стажёра.

Чтобы обновить описания и контакты в уже существующей БД без сброса профилей:

```sh
go run ./cmd/seed-demo -refresh-knowledge
```

В запущенном Docker: `docker compose exec backend seed-demo -refresh-knowledge`.
Команда сначала добавляет недостающие записи, затем явно обновляет только описания
команд, сведения о людях и контакты наставников. Выбор команды и наставника,
заявки, доступы и прогресс сохраняются. Обычный seed продолжает сохранять существующие записи.

## Проверки

```sh
go test ./internal/demoseed -cover
go test -race ./tests/integration/demoseed ./tests/integration/mltools
```

Проверяются готовность встроенных файлов, исходные 2/4, повторная загрузка
после выдачи и регистрации, сохранение настроенного сбоя и откат всех таблиц
при ошибке записи, в том числе внутри демо-провайдера.

При заданной `ACCESS_TEST_DATABASE_URL` дополнительно выполняются PostgreSQL-
варианты: повторная миграция всей схемы, сохранение данных после перезагрузки,
откат при сбое провайдера и полный путь выдачи через HTTP и фонового обработчика.
Команды подготовки отдельной БД — в [инструкции тестов](../backend/tests/integration/README.md).
