# AI-buddy — продуктовая логика MVP

## Цель и пользовательский сценарий

Стажёр знакомится с командой и получает доступ ко всем ресурсам, нужным для своей роли. На экране «Мой план» три карточки, как в макете. [Описание проекта](../README.md)

| Пункт | Что делает стажёр | Результат |
| --- | --- | --- |
| Знакомство с командой | Узнаёт о команде, руководителе и наставнике. | Отмечает знакомство после общения. |
| Рабочие доступы | Через агента запрашивает недостающие доступы по одному. | Сервис подтвердил все обязательные доступы. |
| Первая задача | Видит, какая подготовка нужна перед задачей. | После двух рабочих шагов карточка показывает «Скоро». |

Кнопка «Продолжить адаптацию» открывает следующий шаг. «Путь адаптации» в боковой панели показывает все три этапа. Когда знакомство отмечено и все обязательные доступы выданы, счётчик показывает «2 из 3 этапов».

## Вход и первый запуск

1. Пользователь вводит рабочую почту или внутренний ID из тестового справочника.
2. Backend находит сотрудника и проверяет, заполнен ли его профиль. При наличии профиля стажёр открывает «Мой план», а руководитель — «Заявки команды».
3. Новый стажёр видит назначенную ему команду, выбирает наставника из неё, должность и дату начала стажировки. Backend сверяет выбор со справочником и сохраняет профиль.
4. При следующем открытии или перезагрузке страницы пользователь снова вводит почту или ID. Приложение загружает его сохранённые данные.

Роль и команда заданы в тестовом справочнике сотрудников. Профиль руководителя готовится до демонстрации.

## Знакомство с командой

1. Стажёр открывает «Знакомство с командой». В задании есть краткое описание команды и карточки руководителя и наставника.
2. Если нужны детали, стажёр нажимает «Спросить AI-buddy». В чате можно узнать, чем занимается команда, кто наставник и как с ним связаться.
3. Помощник отвечает по карточке команды. Если сведений мало, уточняет вопрос или подсказывает, к кому обратиться.
4. После общения стажёр нажимает «Отметить знакомство». Backend сохраняет отметку, в плане появляется «Выполнено».

## Рабочие доступы

Список обязательных ресурсов зависит от команды и роли стажёра. Для каждого ресурса заданы уровень доступа, назначение и согласующий. В демо руководитель команды «Поиск» рассматривает заявки на четыре ресурса.

| Ресурс | Уровень доступа | Для чего нужен |
| --- | --- | --- |
| Вики команды | Чтение | Инструкции и процессы команды. |
| YouTrack | Участник проекта | Работа с задачами команды. |
| GitLab, репозиторий `search-api` | `Developer` | Код и работа с ветками. |
| Grafana | Чтение | Дашборды тестового окружения. |

### Действия стажёра

1. Стажёр открывает «Рабочие доступы». В списке «Ресурсы команды» видны назначение и статус каждого ресурса и счётчик выданных доступов. В чате можно спросить, зачем нужен ресурс или где посмотреть заявку.
2. Стажёр просит AI-buddy оформить один доступ. Агент вызывает `prepare_access_request`; backend проверяет права, текущий доступ и активные заявки. Создать заявку вне этого сценария нельзя.
3. В чате агент показывает черновик одного доступа: ресурс, уровень, назначение и согласующего. Стажёр явно подтверждает отправку. Формат подтверждения — сообщение или кнопка в чате — выбирается отдельно.
4. После подтверждения backend ещё раз проверяет условия и создаёт одну заявку `pending` руководителю. Номер и статус видны в разделе «Мои заявки». Без подтверждения сотрудником заявка не создаётся.

### Действия руководителя

1. Руководитель открывает «Заявки команды» и выбирает заявку из очереди.
2. В карточке видит, кто просит доступ, к какому ресурсу, на каком уровне и зачем.
3. Нажимает «Одобрить» или «Отклонить». При отклонении добавляет причину, которую увидит стажёр.
4. После одобрения backend запускает выдачу через тестовый сервис. Счётчик растёт после подтверждения каждого доступа. Пункт «Рабочие доступы» получает «Выполнено», когда подтверждены все обязательные доступы.

### Статусы заявки

| Статус | Что произошло |
| --- | --- |
| На согласовании | Заявка создана и ждёт решения руководителя. |
| Выдаётся | Руководитель одобрил заявку. Сервис обрабатывает выдачу. |
| Доступ выдан | Сервис подтвердил нужный уровень доступа к ресурсу. |
| Отклонена | Руководитель отклонил заявку. Причина доступна в карточке. |
| Ошибка выдачи | Выдача прервалась. В карточке показано, как продолжить. |

В списке «Мои заявки» есть фильтры «Все», «В работе» и «Обработаны». Фильтр «В работе» показывает заявки на согласовании и на выдаче.

### Повторы и ошибки

| Ситуация | Действие системы |
| --- | --- |
| Доступ уже есть | Учитывает его в прогрессе. Новый черновик не создаётся. |
| Заявка уже в работе | Показывает её номер и статус. Новый черновик не создаётся. |
| Подтверждение отправлено повторно | Возвращает ту же заявку, созданную из этого черновика. |
| Заявку отклонили | Показывает причину по этому ресурсу. Можно запросить новый черновик у агента. |
| Права ограничены | Объясняет ограничение и подсказывает доступный следующий шаг. |
| Ошибка при выдаче | Показывает ошибку. Перед повтором проверяет результат предыдущей операции. |

## Чат, профиль и заглушки

У знакомства и рабочих доступов свои вкладки «Задание» и «Чат с AI-buddy». Backend хранит историю для каждого стажёра и пункта. Если стажёр переключился на другое задание, ответ появится в исходном чате. При ожидании ответа или выдачи можно продолжать пользоваться планом.

По аватару открывается профиль с именем, ролью, командой и рабочей почтой. В боковой панели видны три этапа пути, ближайшая демо-встреча с наставником и количество заявок в работе и обработанных.

«Первая задача» ведёт к заглушке. Пока идёт подготовка, карточка показывает нужные шаги. После знакомства и получения всех обязательных доступов она показывает «Скоро».

## Правила MVP

- Backend определяет роль пользователя. Стажёр открывает свои задания, чаты и заявки. Руководитель рассматривает заявки своей команды в пределах своих прав.
- Помощник получает разрешённые сведения о текущем задании. Результат выдачи и прогресс фиксирует backend.
- Для демо используем вымышленные профили и имитации сервисов для всех четырёх ресурсов. Ориентир ТЗ для простых локальных действий — менее одной секунды.

## Порядок демонстрации

1. Войти за стажёра, у которого знакомство ждёт подтверждения, часть доступов выдана и как минимум два можно запросить.
2. Задать вопрос о команде в чате и отметить знакомство.
3. Попросить AI-buddy оформить один доступ, проверить параметры черновика и подтвердить отправку. Показать номер заявки. Повторить для другого ресурса.
4. Перейти к руководителю и одобрить заявки по очереди. После первой выдачи показать, что счётчик вырос, а пункт ещё в работе.
5. После выдачи всех доступов показать «Выполнено», прогресс «2 из 3 этапов» и карточку первой задачи.
