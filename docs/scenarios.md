# Сценарии MVP

## Вход и план

Вход по демо-почте или ID. Команда и роль заданы справочником. Новый стажёр
выбирает должность, наставника своей команды и дату начала стажировки.
При перезагрузке нужен повторный вход; сохранённые данные остаются.

| Этап | Завершение |
| --- | --- |
| Знакомство с командой | Стажёр нажал «Отметить знакомство». |
| Рабочие доступы | Подтверждён нужный уровень по всем обязательным ресурсам. |
| Первая задача | Заглушка: `locked` до завершения первых двух этапов, затем `coming_soon`. |

Общий прогресс после двух рабочих этапов — 2/3. Встреча в боковой панели
задана демо-данными. Знакомство и доступы имеют отдельные чаты.

## Получение доступа

1. Стажёр просит AI-buddy оформить один ресурс из списка обязательных.
2. Go проверяет ресурс, текущий доступ и активные заявки, готовит черновик.
3. Стажёр проверяет ресурс, уровень, назначение и согласующего, подтверждает отправку.
4. Создаётся одна заявка `pending`. Черновик без подтверждения заявки не создаёт.
5. Назначенный руководитель одобряет либо отклоняет с причиной.
6. После одобрения фоновый обработчик выдаёт права через демо-провайдер.
7. Прогресс увеличивается после проверки фактического доступа.

Черновик действует 15 минут. Если срок истёк или параметры изменились,
нужно запросить новый. Публичного маршрута создания черновика нет.

## Заявки

| Статус | Значение |
| --- | --- |
| `pending` | Ожидает решения руководителя. |
| `issuing` | Одобрена, выполняется выдача. |
| `granted` | Нужный уровень доступа подтверждён. |
| `rejected` | Отказ; причина доступна стажёру. |
| `failed` | Ошибка проверки или выдачи; руководитель может повторить обработку. |

Стажёр видит свои заявки: «В работе» — `pending`, `issuing`, `failed`;
«Обработаны» — `granted`, `rejected`. Счётчики рассчитываются до фильтров.
Руководитель видит только назначенные ему `pending`; фильтров нет.
Назначенную карточку можно открыть и после решения, в том числе по ссылке
`/#requests?request=<id>` для повтора `failed`.

| Ситуация | Результат |
| --- | --- |
| Доступ уже выдан | Новый черновик не создаётся. |
| Есть активная заявка | Возвращается существующая заявка. |
| Повтор подтверждения | Возвращается та же заявка. |
| Отказ руководителя | Можно запросить новый черновик. |
| Ошибка выдачи | Повторяется прежняя заявка, сначала проверяются фактические права. |
| Два разных решения | Принимается первое, второе получает 409. |

## Проверка демо

На свежих данных:

1. Войти как `intern-alina`: Вики и YouTrack выданы, прогресс 2/4.
2. Проверить сведения о команде и отметить знакомство.
3. Через чат запросить `gitlab-search-api`, проверить параметры и подтвердить.
4. Войти как `manager-dmitry`, одобрить заявку, дождаться 3/4.
5. Повторить для `grafana-search`, проверить 4/4 и общий прогресс 2/3.
6. Проверить отказ с причиной, повтор подтверждения и чужую заявку.

Автономный frontend-деморежим проходит этот путь на локальных данных.
API-режим использует Go и PostgreSQL, для ответов чата нужен настроенный
ML-сервис с ключом Gemini.
