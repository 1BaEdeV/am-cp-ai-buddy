# Frontend

React, TypeScript, Vite. Единый план, чаты двух этапов, профиль, заявки стажёра
и очередь руководителя. Шрифты и иллюстрации локальные: [источники](THIRD_PARTY.md).

## Запуск

Нужен Node.js 24+. Из папки `frontend`:

```sh
npm ci
npm run dev
```

Адрес: http://127.0.0.1:5173.

## Режимы данных

| Режим                 | Поведение                                                                                  |
| --------------------- | ------------------------------------------------------------------------------------------ |
| `demo` — по умолчанию | Подготовленные ответы, имитация выдачи, данные в браузере. Backend не нужен.               |
| `api`                 | Запросы к Go, PostgreSQL, ответы через ML-сервис. Демо-данные при ошибке не подставляются. |

Для API скопируй `.env.example` в `.env.local`:

```dotenv
VITE_DATA_SOURCE=api
API_PROXY_TARGET=http://127.0.0.1:8080
VITE_API_BASE_URL=/api/v1
```

Docker-сборка по умолчанию использует `api`, nginx проксирует `/api` в Go.
Локальный Vite по умолчанию использует `demo`.

Перезапусти Vite. `/api` проксируется в Go. Для production выполни `npm run build`:
результат находится в `dist`. Хостинг должен проксировать `/api` в Go;
`API_PROXY_TARGET` действует только в режиме разработки.

`ML_TOOLS_TOKEN` и `GEMINI_API_KEY` хранятся на серверах. Переменные `VITE_*`
доступны браузеру. Frontend не вызывает `/internal/ml/tools`.

## Демо

Вход: `intern-alina`, `manager-dmitry`, `intern-ivan`. Иван проходит регистрацию с выбором команды, её должности и наставника.
В API-режиме список «Другие тестовые стажёры» открывает ещё восемь профилей.
После сохранения профиль повторной регистрацией не меняется.
Переключатель ролей доступен только в `demo`. В автономном демо можно выбрать
«Поиск» или «Веб-интерфейсы»; API предлагает все 10 подготовленных команд.

Путь: знакомство → черновик GitLab в чате → подтверждение → одобрение руководителя
→ прогресс 3/4. После Grafana — 4/4, завершены 2/3 этапов, первая задача — «Скоро».
Отказ требует причины. `failed` остаётся активной заявкой.

Данные хранятся в `localStorage`, ключ `ai-buddy-demo-v1`. Удаление ключа
сбрасывает демо после перезагрузки. Вошедший пользователь хранится только
в памяти: обновление страницы снова открывает вход.

## HTTP API

Префикс `/api/v1`. Пользователь передаётся в `X-Demo-Employee-Id`.

| Действие           | Маршрут                                                                |
| ------------------ | ---------------------------------------------------------------------- |
| Вход и регистрация | `POST /auth/login`, `POST /auth/register`                              |
| План               | `GET /onboarding`                                                      |
| Знакомство         | `GET /onboarding/tasks/team-intro`                                     |
| Отметка знакомства | `POST /onboarding/tasks/team-intro/complete`                           |
| Доступы            | `GET /onboarding/tasks/working-accesses`                               |
| Чат                | `GET /onboarding/tasks/{taskId}/chat`                                  |
| Вопрос агенту      | `POST /onboarding/tasks/{taskId}/chat/messages`                        |
| Заявки             | `GET /access-requests`, `GET /access-requests/{id}`                    |
| Подтверждение      | `POST /access-requests/drafts/{id}/confirm`, тело `{"confirmed":true}` |
| Решение            | `POST /access-requests/{id}/decision`                                  |
| Повтор выдачи      | `POST /access-requests/{id}/retry`                                     |

Все эти маршруты зарегистрированы в Go. Отправка вопроса передаёт
`Idempotency-Key`; состояние ответа читается опросом чата. План, заявки и доступы
также обновляются периодически. Недоступный план не подтверждает этапы автоматически.

Карточка заявки: `/#requests?request=<id>`. После входа руководитель может
открыть назначенную заявку в любом статусе, включая `failed` для повтора выдачи.

## Контракт чата

HTTP-клиент `src/lib/api.ts` преобразует ответ Go в формат компонентов:

- `messages[].accessDraft` → `messages[].draft` для карточки подтверждения;
- `latestRun.error.message` → строка `latestRun.error` для сообщения об ошибке.

Серверный контракт: [OpenAPI](../docs/openapi.yaml),
[Go DTO](../backend/internal/chat/types.go).

Черновик содержит `id`, `resourceId`, `approverId`, `parameters`, `createdAt`,
`expiresAt`. UI показывает снимок параметров, срок и кнопку явного подтверждения.
Агент не подтверждает заявку за пользователя.

## Проверки

```sh
npm test
npm run test:coverage
npm run lint
npm run format:check
npm run build
npx playwright install chromium
npm run test:e2e -- --project=desktop --project=mobile --project=api
```

Vitest проверяет вход, регистрацию, план, навигацию, чат, черновики,
решения руководителя, повторы, HTTP-клиент и фоновый опрос.
В покрытие входит весь исполняемый `src`. Исключены тесты, их вспомогательные
файлы и файл TypeScript-типов. Порог CI — **81% отдельно по строкам,
выражениям, функциям и ветвлениям**. Playwright в этот процент не входит.

Отчёты: `coverage/index.html`, `coverage/coverage-summary.json`.
Скриншоты и трассы Playwright: `test-results`. Отчёты не коммитятся.

Для отдельной свежей тестовой PostgreSQL и запущенного Go API с выдачей:

```sh
export LIVE_API_URL=http://127.0.0.1:8088
export LIVE_ML_TOOLS_TOKEN='<токен тестового Go API>'
npm run test:e2e -- --project=live
```

Live-тест создаёт две настоящие заявки. Подготовку вызывает процесс теста,
а чтение чата подменяется фикстурой с полученным черновиком в формате frontend.
Вход, подтверждение, решение и выдача идут через Go и PostgreSQL.
Проверки настоящего ML-ответа и совместимости DTO чата в этом тесте нет.
Без двух переменных live-тест пропускается.
